# 페이지별 기능요구사항 (화물 다단계 브로커리지 투명화)

## 1. 화주 페이지

**목적**: 비정형 화물 요청을 넣으면 AI가 구조화하고, 직접 매칭 가능한 기사 + 운임 적정성을 보여준다.

### 화면 구성
| 영역 | 요소 |
|---|---|
| 좌측 상단 | 팀 로고 이미지 + `집나간 벌꿀오소리` 팀명 |
| 01 · 화물 요청 입력 | 카카오톡/전화 텍스트 입력창(placeholder: "예: 내일 아침 서울→부산 냉장 5톤, 예산 50만원") + 예시 버튼 3개 + [AI 자동 변환] 버튼 |
| 02 · AI 변환 결과 | 출발지/도착지/화물종류/중량/희망운임/상차일시/하차일시. 각 필드는 직접 수정 가능하며 [수정하기]·[재매칭] 액션을 제공 |
| 운임 적정성 배너 | 초록=적정 / 빨강=시세 대비 비정상적으로 낮음. 경고에는 구간 평균과 시세 대비 비율을 함께 표시 |
| 03 · 매칭 기사 | 목록이 아닌 최종 1건. 기사명/차량/차량번호/운행지역/평점/완료율/최근 운행/연락 가능 시간/최소수락운임/선호 도착지역 + [전화하기] 버튼 |

### 사용자 액션
1. 텍스트 입력 (또는 예시 버튼 클릭) → [AI 자동 변환] → 로딩 → AI 변환 결과 표시
2. 필드를 직접 수정하거나 [수정하기]로 편집 상태를 확인 → [재매칭]
3. 수정된 요청으로 운임 적정성·최종 매칭 기사 1건을 다시 계산 → [전화하기]

화주 화면은 인앱 요청/수락 상태를 만들지 않는다. 전화하기는 데모용 `tel:` 링크 또는 안내 모달로 처리한다.

### 필요 API
| 엔드포인트 | 기능 |
|---|---|
| `POST /parse` | 비정형 텍스트 → 편집 가능한 구조화 JSON (LLM 호출, [llm-parsing.md](./llm-parsing.md) 계약 사용) |
| `POST /match` | 구조화 데이터 → 최적 매칭 기사 1명 (기사 현재 위치·활동 출발/도착지·최소수락운임을 점수화한 결과) |
| `GET /fare-check` | 구간+화물종류 → 시세평균, 적정성 판정(정상/경고) |

### 엣지 케이스
- 파싱 실패(너무 모호한 텍스트) → "필수 정보(출발지/도착지/운임)를 다시 확인해주세요" 안내, 예시 버튼 추천
- 매칭 기사 0명 → "현재 매칭 가능한 기사가 없습니다" 안내(데모용 mock 데이터는 1건 이상 매칭되도록 커버리지 확보)
- 시세 데이터 없는 구간/화물종류 → "비교 데이터 없음"으로 표기, 하드 에러 금지

## 2. 기사 페이지

**목적**: 기사가 자신에게 매칭된 오퍼를 확인하고, 운임이 정당한지 보고 수락/거절한다.

### 화면 구성
| 영역 | 요소 |
|---|---|
| 활동 지역 설정 | 현재 출발지·희망 도착지 각각 시/도 1차, 시/군/구 2차 선택. 최초 설정 뒤 수정 가능 |
| AI 선호 조건 | 선택 입력. 예: `부산 서부권 냉장 우선`, `단가보다 귀가 방향 우선` |
| 01 · 추천 화물 | 우측 새로고침 아이콘 버튼 + 세로 스크롤 카드 최대 20건. 본선 UI는 첫 페이지 20건만 표시 |
| 화물 카드 | 상차/하차 태그, 화물 정보, 운임비, 운임 배지(적정/낮음), 낮음일 때 평균 운임 안내 |
| 최적 매칭 | 첫 카드에 강조 테두리와 `✦ AI 최적 매칭` 라벨. 상차지 거리·도착지 거리·선호 일치 이유 표시 |
| 액션 | [수락]과 [숨기기]. `거절`이라는 표현은 사용하지 않음 |

### 사용자 액션
1. mock 기사(`driver-01`)의 현재 출발지·희망 도착지와 선택적인 자연어 선호를 설정 → 추천 화물 첫 페이지 20건 로드
2. 새로고침 버튼 → 같은 조건으로 추천 목록을 다시 조회
3. [수락] 클릭 → 상태 "수락됨"으로 변경(초록 표시), 해당 카드 액션 비활성화
4. [숨기기] 클릭 → 목록에서 즉시 숨김. 새로고침 전까지 다시 표시하지 않음

### 필요 API
| 엔드포인트 | 기능 |
|---|---|
| `GET /drivers/{id}/activity-region` | mock 기사의 현재 출발지·희망 도착지·검색 반경·자연어 선호 조회 |
| `PUT /drivers/{id}/activity-region` | 출발/도착 지역과 선택적인 검색 반경·자연어 선호 설정. 서버가 지역을 좌표로 정규화 |
| `GET /offers?driverId={id}&page=0&size=20` | PostGIS가 필수조건·반경으로 후보를 만들고 AI가 상위 50건을 재랭킹한 추천 페이지. `rankingMode`·거리·기본/AI/최종 점수·추천 이유와 페이지 메타데이터 포함 |
| `POST /offers/{id}/accept` | 오퍼 수락 처리 |
| `POST /offers/{id}/hide` | 오퍼를 현재 추천 목록에서 숨김 |

### 엣지 케이스
- 오퍼 0건 → "현재 매칭된 화물이 없습니다" 안내
- 이미 처리된 오퍼 재클릭 방지(버튼 비활성화 상태 유지)
- 수락·숨김과 활동 지역은 세션 상태로만 유지해도 무방(DB 영속화는 필수 아님 — 데모 스코프)
- `내 수입` 탭과 수입 그래프는 최종 범위에서 제외하고 추천 화물 리스트 영역을 확장한다.
- 추천 점수·동점 처리·mock 테스트 데이터는 [`matching-ranking.md`](./matching-ranking.md)를 따른다.
- AI 호출 실패 시 PostGIS 기본 순위를 반환하고 `rankingMode: RULE_FALLBACK`을 표시한다. 재랭킹 계약은 [`ai-route-ranking.md`](./ai-route-ranking.md)를 따른다.
- 페이지 번호 UI와 무한 스크롤은 본선 범위 밖이지만, `GET /offers`의 페이지 메타데이터는 구현한다.

## 공통 사항
- 모든 API는 **mock/생성 데이터 기반**, 실 데이터 수집 불필요다. OpenAI API는 `POST /parse`와 기사 후보 재랭킹에만 사용하며, 전체 500건을 모델에 전달하지 않는다.
- 화면 2개(화주/기사) 모두 **모바일 대응 불필요** — 데스크톱 브라우저 데모 기준으로 스코프 최소화
- 로딩 상태는 파싱과 AI 추천 새로고침 모두 표시한다. AI 재랭킹이 늦거나 실패해도 PostGIS 기본 추천으로 화면을 완료한다.
