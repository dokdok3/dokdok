# 페이지별 기능요구사항 (화물 다단계 브로커리지 투명화)

## 1. 화주 페이지

**목적**: 비정형 화물 요청을 넣으면 AI가 구조화하고, 직접 매칭 가능한 기사 + 운임 적정성을 보여준다.

### 화면 구성
| 영역 | 요소 |
|---|---|
| 입력 섹션 | 텍스트 입력창(placeholder: "예: 내일 아침 서울→부산 냉장 5톤, 예산 50만원") + 예시 버튼 3개(데모 안정성용 프리셋) + [분석하기] 버튼 |
| 결과 섹션 | ① 파싱결과 카드(출발지/도착지/화물종류/중량/희망운임) ② 매칭 기사 리스트(카드형: 이름/현재위치/차량톤수/거리) ③ 운임 적정성 배너(초록=적정 / 빨강=시세 대비 비정상적으로 낮음, 시세 대비 %) |

### 사용자 액션
1. 텍스트 입력 (또는 예시 버튼 클릭) → [분석하기] → 로딩 → 결과 3종 동시 표시
2. 매칭 리스트에서 기사 선택 → [이 기사에게 요청 보내기] → 해당 기사의 오퍼 목록에 반영

### 필요 API
| 엔드포인트 | 기능 |
|---|---|
| `POST /parse` | 비정형 텍스트 → 구조화 JSON (LLM 호출) |
| `POST /match` | 구조화 데이터 → 매칭 기사 리스트 (거리·차량조건 기준 정렬) |
| `GET /fare-check` | 구간+화물종류 → 시세평균, 적정성 판정(정상/경고) |
| `POST /requests` | 화주가 특정 기사에게 요청 전송 → 상태 생성(대기중) |

### 엣지 케이스
- 파싱 실패(너무 모호한 텍스트) → "필수 정보(출발지/도착지/운임)를 다시 확인해주세요" 안내, 예시 버튼 추천
- 매칭 기사 0명 → "현재 매칭 가능한 기사가 없습니다" 안내(데모에서는 발생 안 하게 mock 데이터 커버리지 확보 필요)
- 시세 데이터 없는 구간/화물종류 → "비교 데이터 없음"으로 표기, 하드 에러 금지

## 2. 기사 페이지

**목적**: 기사가 자신에게 매칭된 오퍼를 확인하고, 운임이 정당한지 보고 수락/거절한다.

### 화면 구성
| 영역 | 요소 |
|---|---|
| 상단 | 기사 선택 드롭다운(로그인 대체, 데모용 — 기사 A/B/C 등) |
| 오퍼 목록 | 카드형: 출발지→도착지, 화물종류, 제시운임, 운임 적정성 배지(초록/빨강), [수락]/[거절] 버튼 |
| (스트레치) 내 수입 탭 | 아래 3번 참고 |

### 사용자 액션
1. 기사 선택 → 해당 기사에게 매칭된 오퍼 목록 로드
2. [수락] 클릭 → 상태 "수락됨"으로 변경(초록 표시), 버튼 비활성화
3. [거절] 클릭 → 상태 "거절됨"으로 변경(회색 표시), 버튼 비활성화

### 필요 API
| 엔드포인트 | 기능 |
|---|---|
| `GET /offers?driverId={id}` | 특정 기사에게 매칭된 오퍼 목록 조회 |
| `POST /offers/{id}/accept` | 오퍼 수락 처리 |
| `POST /offers/{id}/reject` | 오퍼 거절 처리 |

### 엣지 케이스
- 오퍼 0건 → "현재 매칭된 화물이 없습니다" 안내
- 이미 처리된 오퍼 재클릭 방지(버튼 비활성화 상태 유지)
- 수락/거절은 세션 상태로만 유지해도 무방(DB 영속화는 필수 아님 — 데모 스코프)

## 3. (스트레치) 기사 페이지 — "내 수입" 탭

**목적**: 다단계 착취 문제(차주 실수령 70% 미만)를 개인화된 숫자로 증명. 여유 있을 때만 추가.

### 화면 구성
| 영역 | 요소 |
|---|---|
| 요약카드 3개 | 총 완료건수 / 총 수입 / 평균 시세 대비 수령률(%) |
| 그래프 | 최근 5~8건 "받은운임 vs 정상시세" 막대그래프 |

### 필요 API
| 엔드포인트 | 기능 |
|---|---|
| `GET /drivers/{id}/history` | 완료 이력(날짜/구간/화물종류/받은운임) + 시세 대비 비율 계산 |

### 데이터
완료 이력 mock 5~8건 (기존 시세표 데이터 재활용, 신규 소스 불필요)

## 공통 사항
- 모든 API는 **mock/생성 데이터 기반**, 실 데이터 수집 불필요 (당일 구현 원칙)
- 화면 2개(화주/기사) 모두 **모바일 대응 불필요** — 데스크톱 브라우저 데모 기준으로 스코프 최소화
- 로딩 상태는 반드시 표시 (LLM 호출 시 1~3초 지연 발생 가능 — 스피너 없으면 "멈춘 것처럼" 보여 데모 리스크)
