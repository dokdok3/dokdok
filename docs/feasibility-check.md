# 구현 가능성 검토 — 팀 구성 2BE/2FE/1기획, 9:00~18:00(9시간) 단일 개발일

환경 세팅은 사전 완료 전제. 9시간은 순수 기능 개발+통합+데모 준비 시간.
심사 기준(창의성/현업유관성)은 이미 채점 완료(`judge-results.md`) — 여기서는 "당일 실제로 완성되는가"만 별도로 검토.

## 평가 기준

- **AI 구현 난이도**: pretrained 모델/LLM API로 때울 수 있는가, 커스텀 학습이 필요한가
- **데이터 확보 리스크**: 9시간 내 확보 가능한 데이터로 설득력 있는 데모가 되는가 (실데이터 없으면 시뮬레이션/mock 데이터의 그럴듯함이 중요)
- **프론트 복잡도**: 지도 API·실시간 시각화 등 프론트 공수
- **통합 리스크**: BE-FE 붙이는 컴포넌트 수, 실패 지점

## 결론 (이 시점 기준)

이 단계에서는 C10(고속도로 2차사고 예방 AI)이 심사 점수 1위이면서 구현 난이도도 가장 낮은 후보로 판단됐다. 이후 멘토 1차 브리핑을 거쳐 "물류/화물이 해커톤의 명시적 타깃 영역"이라는 점이 확인되면서 최종적으로는 C13(화물 다단계 브로커리지 투명화)이 선정됐다 — 경위는 `final-scoring.md` 참고.
