## [메시지 1/4] 프로젝트 개요 + 최종 선정 주제

**🚚 카카오모빌리티 물류 해커톤 준비 요약**

**최종 선정 주제: 화물 다단계 브로커리지 투명화**

화주가 카톡/전화/엑셀로 보낸 비정형 화물요청을 LLM이 자동 구조화하고, 다단계 브로커 없이 차주와 직접 매칭 추천, 운임이 시세보다 비정상적으로 낮으면 경고하는 서비스.

**문제 배경**: 화물 운송의 32.1%가 3단계 이상 다단계 계약, 차주 실수령은 최초 운송료의 70% 미만. 소수 화물앱이 물동량 90% 이상 독점하며 수수료 20% 이상 부과. 화주는 여전히 비정형 채널로 화물 정보를 흘려보내 다단계가 계속 끼어드는 구조.

## [메시지 2/4] 왜 이 주제인가 (멘토 브리핑 + 심사 재검증)

**카카오모빌리티 멘토 세션(산업기획팀) 직접 확인 내용**:

**"물류/화물"이 해커톤의 명시적 타깃 영역** — 5대 서비스 분류(에이전트/카오너향/마스/물류와데이터/자율주행) 중 "오늘 모여주신 분들이 고민해 주실 영역"으로 직접 지목.

**회사가 스스로 인정한 미해결 갭 (원문)**:
> "시장을 분석하다 보면... 정산의 측면, 배차의 측면 다양한 측면들이 아직까지는 디지털화해 볼 수 있는 여지가 있다"

→ **매칭 추천 = "배차" 갭**, **운임 적정성 스코어링 = "정산" 갭**을 정확히 겨냥.
(참고: 기존 TMS는 이미 화주향 모니터링+클러스터링 동선최적화를 제공 중이라, 이걸 재현하는 아이디어는 피했음)

**본선 공식 배점(창의성40/현업활용성30/AI활용20/구현수준10, 참여기업 임직원 100% 평가)으로 블라인드 재검증한 결과**: 이 주제가 후보군 중 현업 유관성 항목 유일 만점(5/5) 획득.

## [메시지 3/4] 핵심 기능 & 결과물 형태

**핵심 기능 3단계**
1. **파싱**: 카톡/전화 텍스트("내일 서울→부산 냉장5톤 예산50만원") → LLM이 자동으로 출발지/도착지/화물종류/중량/희망운임 구조화
2. **매칭**: 다단계 재하도급 없이 차주와 직접 매칭 추천
3. **운임 검증**: 제시 운임이 구간 평균 시세보다 비정상적으로 낮으면 경고

**결과물**: 웹앱 (설치파일 제출 불가 규정상 배포 URL 필수)
- 화주 페이지: 요청 입력 → 편집 가능한 AI 변환 결과 → 운임경고 배너 → **최종 매칭 기사 1명** → 전화하기
- 기사 페이지: 활동지역 설정 → 추천 화물 첫 페이지 최대 20건(첫 카드 최적 매칭 강조) → 운임 적정성 배지 → 수락/숨기기

기사 등록화면은 안 만듦 — mock 차주 데이터가 이미 등록된 상태라는 전제로 시작 (AI 무관한 CRUD라 시간 대비 효율 낮음).
LLM은 `POST /parse`에서만 사용하고, 매칭·운임 판정은 mock 데이터의 규칙 기반으로 처리. 프롬프트·응답 JSON 계약은 `docs/llm-parsing.md` 참고.
