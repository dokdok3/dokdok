# 최종 팀 배치 & 시간표 (팀 '집나간 벌꿀오소리' — 화물 다단계 브로커리지 투명화)

전제: 2BE/2FE/1기획, 개발환경·배포파이프라인 사전세팅 완료, **백엔드는 Java(Spring Boot) 확정**, **와이어프레임 사전 확정 완료**(`wireframe.html`·`wireframe-notes.md` 참고). 본선 당일 09:00~18:00 안에 핵심구현+배포+영상+보고서+제출까지 전부 끝내야 함(제출기한 18:00, 그 이후는 심사 제외 가능).

## 사전 준비 (본선 이전 — 규정상 허용)
- GitHub 저장소 생성 + Vercel(또는 유사 플랫폼) 연결해서 push하면 자동배포되게 세팅
- LLM API 키 발급·백엔드 환경변수 세팅 + [`llm-parsing.md`](./llm-parsing.md)의 프롬프트/테스트 케이스 사전 확인
- 팀 전원 로컬 개발환경 세팅 확인
- **와이어프레임 확정**(`wireframe.html`): 화주 페이지(파싱결과 필드 수정 → 운임경고 배너 → 최적 매칭 차주 1명 → 전화하기), 기사 페이지(활동지역 설정 → 추천 화물 첫 페이지 카드 최대 20건 → 수락/숨기기) 화면 구성 합의 완료
- **매칭 로직 확정**([`matching-ranking.md`](./matching-ranking.md) 참고): 실시간 경매 방식 배제, 화물종류·최소수락운임 필터 뒤 기사 현재 위치/활동 출발지/활동 도착지/운임을 정적 점수화
- **API 계약 확정**(`prd.md` 4번 참고): 화주 측은 `POST /requests` 같은 인앱 요청 사이클 없이 "전화하기"로 종료, 기사 측만 `GET /offers`+accept/hide 흐름 유지

## 팀 배치

| 역할 | 담당 |
|---|---|
| **백엔드1** | 사전 생성한 화물요청 500건 seed 연동·검증(기사 추천 20건+페이지 검증), 차주 20~30명(이름/차량/차량번호/운행지역/평점/완료율/최근운행/연락가능시간/최소수락운임/선호지역), 구간별 시세표 + LLM 파싱 API(`POST /parse`, 상차/하차일시 포함) |
| **백엔드2** | 매칭 스코어링 로직(`POST /match`·`GET /offers`: 현재 위치/활동 출발지/활동 도착지/운임 점수화) + 운임 적정성(`GET /fare-check`) + 기사 추천피드·수락/숨기기(`GET /offers`, `POST /offers/{id}/accept`·`/hide`) API |
| **프론트1** | 화주 페이지: 텍스트 입력 → AI 변환 결과(필드별 수정 가능) → 운임 경고 배너 → 최적 매칭 차주 1명 카드 → 전화하기 버튼 |
| **프론트2** | 기사 페이지: 활동지역(출발/도착 시·도·시군구) 설정 → 추천 화물 카드 5건(최적매칭 강조) → 운임 배지 → 수락/숨기기 |
| **기획** | 데모 시나리오·30초 훅 대본(멘토 발언 인용) · PDF 보고서 · 심사 대응자료 · 영상 촬영 총괄 |

*트럭기사 등록 화면은 만들지 않음 — mock 차주 데이터가 "이미 등록된 상태"라는 전제로 시작.*
*화주 쪽은 시스템 내 요청/수락 사이클 없이 "전화하기"로 종료 — 인앱 요청 플로우는 `prd.md` 7번(추후 개선 항목)으로 이관.*
*"내 수입" 탭은 와이어프레임 확정 단계에서 최종 제외 — `prd.md` 7번 참고. 아래 시간표에서도 별도 스트레치 항목으로 다루지 않는다.*
