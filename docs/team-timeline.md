# 최종 팀 배치 & 시간표 (C13 화물 다단계 브로커리지 투명화)

전제: 2BE/2FE/1기획, 개발환경·배포파이프라인 사전세팅 완료, 본선 당일 09:00~18:00 안에 핵심구현+배포+영상+보고서+제출까지 전부 끝내야 함(제출기한 18:00, 그 이후는 심사 제외 가능).

## 사전 준비 (본선 이전 — 규정상 허용)
- GitHub 저장소 생성 + Vercel(또는 유사 플랫폼) 연결해서 push하면 자동배포되게 세팅
- LLM API 키 발급·환경변수 세팅
- 팀 전원 로컬 개발환경 세팅 확인

## 팀 배치

| 역할 | 담당 |
|---|---|
| **백엔드1** | mock 데이터 생성(화물요청 예시, 차주 20~30명, 구간별 시세표) + LLM 파싱 API |
| **백엔드2** | 매칭 추천 로직 + 운임 적정성 스코어링 로직 + 수락/거절 상태 관리 API |
| **프론트1** | 화주 페이지 (요청 입력 → 파싱결과 테이블 → 매칭기사 리스트 → 운임경고 배너) |
| **프론트2** | 기사 페이지 (기사 선택 드롭다운 → 오퍼목록 → 운임 적정성 배지 → 수락/거절 버튼) |
| **기획** | 데모 시나리오·30초 훅 대본(멘토 발언 인용) · PDF 보고서 · 심사 대응자료 · 영상 촬영 총괄 |

*트럭기사 등록 화면은 만들지 않음 — mock 차주 데이터가 "이미 등록된 상태"라는 전제로 시작.*

## 스트레치 목표: 기사 "내 수입" 탭 (필수 아님, 여유 있으면 추가)

등록화면과 달리 이건 넣을 가치가 있음 — 핵심 문제(차주 실수령 70% 미만)를 개인화된 숫자로 직접 증명하는 화면이라 현업 유관성을 강화함.

- **구성**: 요약카드 3개(총 완료건수/총수입/평균 시세대비 수령률%) + 최근 5~8건 "받은운임 vs 정상시세" 막대그래프
- **필요 데이터**: 완료 이력 mock 5~8건(날짜/구간/화물종류/받은운임) — 기존 시세표 데이터 재활용, 신규 소스 불필요
- **담당**: 프론트2 (기사 페이지에 탭으로 추가)
- **타이밍**: 15:00~16:00 통합테스트 여유 시간에, 핵심 플로우(오퍼목록·수락/거절)가 먼저 안정화된 경우에만 추가. 시간 부족하면 과감히 스킵 — 핵심 3단계(파싱→매칭→운임경고) 완성이 항상 우선
